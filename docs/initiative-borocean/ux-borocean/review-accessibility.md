# Accessibility Review — Karşılama Sayfası (/)

## Verdict

The new section is mostly accessibility-sound: the hero CTA's color pair (`--accent` on `--accent-text` and vice versa) computes to ≈5.35:1, clearing AA for normal text, and the rendered "Üretimde" badges (green on 15%-opacity green over `--surface-elevated`) compute to ≈6.2:1 — both genuinely pass, and the three-card differentiation relies on heading text, not color alone, so the existing "yön bilgisi yalnızca renkle verilmez" floor rule isn't violated. But there are real gaps a literal implementer would hit: a dormant badge CSS class that reintroduces an already-fixed low-contrast pattern, an unspecified/likely-too-small click target on the "Giriş Yap" link under WCAG 2.2 SC 2.5.8, an undocumented responsive commitment for the hero grid, a broken heading outline (h1 → h3, no h2 anywhere), and decorative icons shipped without `aria-hidden`. None of these are visual-redesign asks — they're spec/mock precision gaps.

## Findings

- **medium** Dormant `.tag.soon` badge reintroduces a pattern already fixed elsewhere as a serious violation (`mockups/key-landing.html:28,78`)
  `--accent` (#3B82F6) text at 15% opacity over `--surface-elevated` computes to ≈3.6:1, well under AA's 4.5:1 — essentially the same failure mode as the Settings "aktif chip/rozet" bug in `a11y-audit-2026-10-10.md` (flagged "ciddi", 4.2:1, fixed by switching badge text to primary color + border for state). The rendered markup only uses `.tag.live` (green, which passes at ≈6.2:1 because green is more luminant), so this isn't live yet — but the blue `.tag.soon` rule sits in the CSS ready to be used (e.g. if a future "Yakında" status is added to one of the three cards) and would silently fail AA again.
  Fix: delete the unused `.tag.soon` rule from the mock, or change it to `color: var(--text-primary)` with a border/dot for state (matching the Settings fix pattern), and add a line to EXPERIENCE.md row 5 noting status tags must follow the same no-color-only, AA-checked pattern already established for Settings badges.

- **high** No committed minimum click target for the "Giriş Yap" top-bar link under WCAG 2.2 SC 2.5.8 (EXPERIENCE.md row 1; `mockups/key-landing.html:46,125` `.loginlink`)
  The existing Accessibility Floor's touch-target rule ("Mobilde dokunma hedefleri en az 44pt `[ASSUMPTION]`") is explicitly scoped to mobile, so it doesn't apply to this web-only page. `.loginlink` is a 13px, unpadded, standalone link (not inline within a sentence, so it likely doesn't qualify for 2.5.8's inline-text-block exception) — as specified, its realized hit area is well under the 24×24 CSS px minimum WCAG 2.2 AA requires. This is also the exact risk the task brief flagged: de-emphasizing "Giriş Yap" to a plain text link with no border/button semantics and no stated hit-area makes it easy to ship under-sized for returning users.
  Fix: add a line to EXPERIENCE.md's Karşılama Sayfası row 1 (or Accessibility Floor) stating a web minimum click target, e.g. "Web bağlantı ve düğmelerde en az 24×24px tıklama alanı (WCAG 2.2 SC 2.5.8)"; give `.loginlink` explicit padding in the mock (e.g. `padding:8px 4px;display:inline-block`) so the specified target clears 24px.

- **medium** Hero's two-column → one-column collapse is a mock-only decision, not committed in EXPERIENCE.md (EXPERIENCE.md line 64; `mockups/key-landing.html:99-101`)
  EXPERIENCE.md only commits to a wider max-width ("`max-w-5xl` `[ASSUMPTION]`") for the hero/problem sections; it says nothing about the two-column hero (text + screenshot placeholder) collapsing to one column, nor at what breakpoint. The mock's `@media (max-width: 760px){.hero,.groups,.triad{grid-template-columns:1fr}}` handles this correctly, but because EXPERIENCE.md explicitly states "bu belge ile bir mock çeliştiğinde bu belge geçerlidir," a developer following the spine text literally — and treating the mock as merely illustrative per its own header comment — could ship a fixed two-column grid that doesn't reflow, risking WCAG 1.4.10 Reflow (AA) at narrow web widths.
  Fix: add a bullet under the Karşılama Sayfası table committing to the collapse, e.g. "Hero, özellik ve üç-görüş ızgaraları `< 760px` genişlikte tek sütuna döner (WCAG 1.4.10 reflow)."

- **medium** Heading hierarchy skips from `<h1>` straight to `<h3>`; section titles aren't headings at all (`mockups/key-landing.html:131,153,152,157,163,171`)
  There is exactly one `<h1>` (hero title) and then every subsequent heading-looking element is `<h3>` (feature cards, triad cards) — no `<h2>` anywhere on the page. The group labels "Araştır / Takip Et / Karar Desteği" (`.group-label`) and the section title "Aynı hisseye üç ayrı görüş" (`.sec-title`) are styled `<p>` tags, not headings, so screen-reader users navigating by heading (a primary AT navigation pattern) cannot jump to any of these sections and the outline is logically broken. EXPERIENCE.md rows 4–5 describe these as groupings/section titles but don't require real heading markup.
  Fix: in EXPERIENCE.md rows 4 and 5, state that "Araştır/Takip Et/Karar Desteği" and "Aynı hisseye üç ayrı görüş" must render as `<h2>` (feature/triad card titles remain `<h3>`); update the mock's `.group-label` and `.sec-title` elements to `<h2>` tags (keep current visual styling via the existing CSS classes).

- **low** Decorative SVG icons ship without `aria-hidden` (`mockups/key-landing.html:133,137,195,202`)
  The CTA arrow icons, the shotplaceholder camera-outline icon, and the trust-band shield icon are purely decorative and redundant with adjacent visible text ("Ücretsiz Başla", the placeholder caption, the trust sentence) — unlike the logo SVG, which correctly carries a meaningful `aria-label`. This isn't a regression of a fixed bug (unlabeled SVGs without a `role` are usually excluded from the accessibility tree by default in most browsers/AT), but EXPERIENCE.md's Accessibility Floor only states the mobile rule for icon-*only* buttons needing `accessibilityLabel` — it has no equivalent web guidance for hiding redundant decorative icons, so this is a floor gap rather than a violation of an existing rule.
  Fix: add a bullet to the Accessibility Floor, e.g. "Web'de salt dekoratif simgeler `aria-hidden="true"` taşır; buton/bağlantı metniyle aynı bilgiyi tekrarlamaz," and add `aria-hidden="true"` to the three decorative SVGs in the mock.
